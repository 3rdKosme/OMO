## Строки 28–31: обучение

```python
prior = np.array([np.mean(y_train == c) for c in classes])
mean = np.array([x_train[y_train == c].mean(axis=0) for c in classes])
var = np.array([x_train[y_train == c].var(axis=0) for c in classes])

Здесь всё обучение — три строки.

### Строка 29 — априорные вероятности

- `y_train == c` — массив True/False, True у объектов класса c.
- `np.mean` от True/False — доля True (True считается как 1, False как 0). Это

- Результат `prior = [0.5, 0.5]`.

### Строка 30 — средние

- `x_train[y_train == c]` — булева маска выбирает только строки класса c: матрица 50×2.
- `.mean(axis=0)` — среднее по строкам, то есть отдельно по каждому столбцу. Получаются
  два числа (μ₁, μ₂).
- `mean` — матрица 2×2: строка = класс, столбец = признак.

```
mean = [[3.428, 0.246],    # класс -1
        [2.770, 1.326]]    # класс +1
```

### Строка 31 — дисперсии

- `.var(axis=0)` — дисперсия по каждому столбцу. По умолчанию NumPy делит на n
  (`ddof=0`), это оценка максимального правдоподобия.
- `var` — тоже 2×2:

```
var = [[0.14082, 0.01088],

## Строки 38–40: логарифм гауссовской плотности

```python
def log_gauss(x, mu, s2):
    return -0.5 * np.log(2 * np.pi * s2) - (x - mu) ** 2 / (2 * s2)
```

Формула ln p(x | μ, σ²) = −½·ln(2πσ²) − (x − μ)²/(2σ²).

Работает сразу для массивов за счёт **broadcasting**. Например, в `scores` вызывается
`log_gauss(x, mean[k], var[k])`, где:

- `x` — матрица N×2 (N объектов);
- `mean[k]`, `var[k]` — векторы из 2 чисел (параметры класса k для x₁ и x₂).

NumPy «растягивает» векторы на все N строк, и получается матрица N×2: в столбце 0 —
ln p(x₁ | класс k), в столбце 1 — ln p(x₂ | класс k) для каждого объекта.

Логарифм берётся вместо самой плотности, чтобы произведение плотностей превратилось
в сумму и не было проблем с очень маленькими числами.

---

## Строки 43–46: оценки классов

```python
def scores(x):
    return np.array([np.log(prior[k]) + log_gauss(x, mean[k], var[k]).sum(axis=1)
                     for k in range(len(classes))]).T
```

Для каждого класса k:

- `log_gauss(...).sum(axis=1)` — сумма по признакам: ln p(x₁ | y) + ln p(x₂ | y).
  Сумма логарифмов = логарифм произведения, это и есть «наивное» предположение
  p(x | y) = p(x₁ | y)·p(x₂ | y). Результат — вектор из N чисел.
- `+ np.log(prior[k])` — добавляем ln P(y).

Список из двух векторов превращается в массив 2×N, `.T` транспонирует его в N×2:
строка = объект, столбец 0 — оценка класса −1, столбец 1 — класса +1.

## Строки 49–50: предсказание

```python
def predict(x):
    return classes[np.argmax(scores(x), axis=1)]
```

- `np.argmax(..., axis=1)` — для каждой строки номер столбца с наибольшей оценкой: 0 или 1.
- `classes[...]` превращает номера в классы: 0 → −1, 1 → +1.

Это правило a(x) = argmax_y [ln P(y) + Σⱼ ln p(xⱼ | y)].

## Строки 59–67: апостериорные вероятности

```python
s = scores(x_train)
post = np.exp(s - s.max(axis=1, keepdims=True))
post = post / post.sum(axis=1, keepdims=True)
```

Перевод оценок в вероятности P(y | x) по формуле Байеса:
P(k | x) = e^{sₖ} / (e^{s₀} + e^{s₁}).

- `s.max(axis=1, keepdims=True)` — максимум в каждой строке, `keepdims=True` оставляет форму
  N×1, чтобы вычитание шло построчно.
- Вычитание максимума ничего не меняет в результате (множитель e^{−max} сокращается
  в дроби), но не даёт `np.exp` переполниться или уйти в 0. Например, для объекта
  (3.0; 1.3) оценки около −51 (класс −1) и −0.01 (класс +1); e^{−51} ≈ 10⁻²² ещё считается, но на других данных
  можно получить e^{−1000} = 0 у обоих классов и деление 0/0.
- Деление на сумму по строке нормирует вероятности, чтобы P(−1 | x) + P(+1 | x) = 1.

```python
for i in np.argsort(np.abs(post[:, 1] - 0.5))[:5]:
```

- `np.abs(post[:, 1] - 0.5)` — насколько вероятность класса +1 далека от 0.5. Чем меньше,
  тем объект ближе к границе и классификатор менее уверен.
- `np.argsort(...)[:5]` — индексы 5 объектов с наименьшим значением, то есть самых спорных.

Вывод:

```
Объект       | y  | P(-1|x)  P(+1|x) | a(x)
(3.5, 0.6)   | -1 | 0.9867   0.0133   | -1
(3.3, 0.5)   | -1 | 0.9996   0.0004   | -1
(2.3, 0.3)   | -1 | 1.0000   0.0000   | -1
(3.4, 0.4)   | -1 | 1.0000   0.0000   | -1
(3.4, 0.4)   | -1 | 1.0000   0.0000   | -1
```

Даже у самого спорного объекта вероятность своего класса 0.987. Объект (3.4, 0.4)
встречается в выборке дважды, поэтому выведен два раза.

### Проверка вручную для (3.5; 0.6)

| | Класс −1 | Класс +1 |
|---|---|---|
| ln P(y) | −0.6931 | −0.6931 |
| ln p(x₁ \| y) | 0.0428 | −2.5110 |
| ln p(x₂ \| y) | −4.4156 | −6.1647 |
| Оценка s | −5.0659 | −9.3688 |

Разность −9.3688 − (−5.0659) = −4.303, P(+1 | x) = 1/(1 + e^{4.303}) = 0.0133, как в программе.
Основной вклад даёт x₂ = 0.6: для класса −1 он выше среднего на 3.4σ, но для класса +1
ниже среднего на 3.7σ, а x₁ = 3.5 ближе к центру класса −1.

## Строки 69–73: сетка для границы

```python
g1, g2 = np.meshgrid(np.linspace(1.8, 4.6, 300), np.linspace(0, 2.2, 300))
grid = np.c_[g1.ravel(), g2.ravel()]
s = scores(grid)
diff = (s[:, 1] - s[:, 0]).reshape(g1.shape)
```

Граница наивного Байеса — кривая, поэтому её не нарисовать по двум точкам, как прямую в
ЛР3–ЛР4. Вместо этого считаем классификатор в каждой точке сетки:

- `meshgrid` строит сетку 300×300: `g1` — координаты x₁ всех узлов, `g2` — координаты x₂.
- `ravel()` вытягивает матрицу в вектор, `np.c_[...]` склеивает два вектора в столбцы:
  `grid` — матрица 90000×2, все узлы сетки как «объекты».
- `scores(grid)` — оценки обоих классов в каждом узле.
- `diff` = s₊ − s₋ = Γ(x): > 0 — область класса +1, < 0 — класса −1, = 0 — граница.
  `reshape` возвращает форму 300×300 для рисования.

# Часть 2. Разбор `task6.py` (задание 6)

Программа приближает функцию варианта 7 полиномом 13-й степени по формуле МНК —
сначала без регуляризации, потом с L2-регуляризатором — и сравнивает результаты.

## Строки 5–7: функция варианта

```python
def f(x):
    return x ** 4 - 10 * x ** 3 + 20 * x ** 2 - 100 * x
```

f(x) = x⁴ − 10x³ + 20x² − 100x. Работает и для числа, и для массива NumPy (поэлементно).

---

## Строки 10–12: отсчёты

```python
x = np.arange(0, 10.05, 0.1)
y = f(x)
N = 13
```

- `np.arange(0, 10.05, 0.1)` — числа 0, 0.1, …, 10. Верхняя граница не включается, поэтому
  стоит 10.05, а не 10: иначе из-за погрешности дробных чисел точка 10 могла бы
  потеряться. Получается 101 отсчёт.
- `y` — значения функции во всех отсчётах (от −766 до 1000).
- `N` — степень полинома, весов N + 1 = 14.

---

## Строки 14–16: матрица признаков и обучающая выборка

```python
X_all = np.array([[a ** n for n in range(N + 1)] for a in x])
X = X_all[::2]
Y = y[::2]
```

- Для каждого отсчёта `a` строится строка (a⁰, a¹, …, a¹³) = (1, a, …, a¹³). `X_all` — матрица
  101×14 для всего диапазона; прогноз модели на всех отсчётах — `X_all @ w`.
- `[::2]` — срез с шагом 2: строки с индексами 0, 2, 4, …, 100. Это обучающая выборка из
  задания (чётные индексы): `X` — 51×14, `Y` — 51 значение.
- `[1::2]` (дальше в коде) — нечётные индексы 1, 3, …, 99, отсчёты, которые в обучении
  не участвуют.

Последний столбец X содержит x¹³: при x = 10 это 10¹³, а первый — единицы. Из-за этого
разброса и возникают все численные проблемы.

---

## Строки 17–18: размеры и обусловленность

```python
print("Число обусловленности X^T X = %.2e" % np.linalg.cond(X.T @ X))
```

`np.linalg.cond` — число обусловленности: во сколько раз может усилиться ошибка при
решении системы с этой матрицей. Получается 1.92·10²⁸ — больше, чем 1/ε ≈ 4.5·10¹⁵ для
double, т.е. обращать такую матрицу бессмысленно.

---

## Строки 21–22: средняя квадратичная ошибка

```python
def mse(a, b):
    return np.mean((a - b) ** 2)
```

MSE = среднее (aᵢ − bᵢ)². Используется для сравнения моделей.

---

## Строки 25–31: решение без регуляризации

```python
w = np.linalg.inv(X.T @ X) @ X.T @ Y
a = X_all @ w
```

- Это формула из задания w = (XᵀX)⁻¹XᵀY: `X.T` — транспонирование, `@` — матричное
  умножение, `np.linalg.inv` — обратная матрица.
- Операции `@` выполняются слева направо: (XᵀX)⁻¹ (14×14) · Xᵀ (14×51) · Y (51) → вектор
  из 14 весов.
- `a` — прогнозы на всех 101 отсчёте.

Результат: веса порядка 10⁴ с чередующимися знаками, MSE ≈ 10⁸ и на обучающих, и на
остальных отсчётах. Модель не совпадает с функцией нигде (левый график).

`np.array2string(w, precision=4)` печатает массив с 4 значащими цифрами в
экспоненциальной записи — веса различаются на 13 порядков, иначе их не прочитать.

## Строки 33–39: перебор λ

```python
for lam_i in [0.01, 1, 10, 100, 1000, 10000, 100000]:
    w_i = np.linalg.inv(X.T @ X + lam_i * np.eye(N + 1)) @ X.T @ Y
    a_i = X_all @ w_i
```

- `np.eye(N + 1)` — единичная матрица 14×14, `lam_i * np.eye(...)` — λI.
- Формула w = (XᵀX + λI)⁻¹XᵀY считается для нескольких λ, для каждого печатаются
  ошибки на обучающих (`[::2]`) и остальных (`[1::2]`) отсчётах и норма весов ‖w‖.

```
  lambda  | MSE обуч. | MSE остальн. |   |w|
     0.01 | 4703158.13 |   4474786.84 | 5.85e+03
        1 |  73156.52 |     66346.13 | 1.08e+03
       10 |   5009.31 |      4853.63 | 1.63e+02
      100 |    353.83 |       304.69 | 7.19e+01
     1000 |   1202.73 |      1225.15 | 9.26e+00
    10000 |   2844.48 |      2895.38 | 1.80e+00
   100000 |   4173.00 |      4256.93 | 3.65e+00
```

С ростом λ веса уменьшаются, ошибка сначала резко падает, а при λ ≥ 10⁴ снова растёт
(недообучение). Минимум в этом прогоне — при λ = 100, но при λ ≤ 100 матрица ещё
достаточно плохая, чтобы результат сильно зависел от мелких деталей вычислений
(при другом способе построения X ошибка при λ = 100 получалась ~6000). λ = 1000
даёт близкий результат и устойчивее, поэтому взят он.

## Строки 41–49: итоговая модель с L2

```python
lam = 1000
w_l2 = np.linalg.inv(X.T @ X + lam * np.eye(N + 1)) @ X.T @ Y
a_l2 = X_all @ w_l2
```

Та же формула с λ = 1000. Веса — порядка единиц и меньше, ‖w‖ = 9.3, MSE ≈ 1200 на
обеих частях отсчётов (в среднем ошибка ~35 при размахе функции 1766). На правом графике
модель совпадает с f(x) почти везде, заметное отклонение (до 89) только при x < 3:
регуляризатор сильнее всего сжимает младшие коэффициенты, которые отвечают за
поведение около нуля.

Число обусловленности уменьшилось на три порядка (до 1.25·10²⁵): λ = 1000 мало по сравнению
с наибольшим собственным значением ~10²⁶, но поднимает почти нулевые собственные значения,
и обращение становится намного устойчивее.

---

## Строки 51–56: проверка через lstsq

```python
w_ls = np.linalg.lstsq(X, Y, rcond=None)[0]
```

- `np.linalg.lstsq` решает ту же задачу min ‖Y − Xw‖², но через SVD-разложение самой X,
  не формируя XᵀX и не обращая её. Число обусловленности X — корень из cond(XᵀX),
  примерно 10¹⁴, это ещё в пределах точности double.
- `[0]` — сами веса (функция возвращает ещё остатки, ранг и сингулярные числа).

Результат: MSE ≈ 0.05 на обеих частях отсчётов. f(x) — полином 4-й степени, полином 13-й
степени описывает его точно, и правильно посчитанный МНК находит это решение. Значит,
расхождение модели без регуляризации вызвано не самой моделью, а явным обращением
плохо обусловленной матрицы, о чём и написано в выводах.
